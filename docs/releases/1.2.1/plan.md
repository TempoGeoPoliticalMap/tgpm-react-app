# Mobile View: Navigate to Wikipedia on Image Click

## Context

The mobile card list introduced in 1.2.0 already links the event *title* to its Wikipedia (or Wikidata) page. The thumbnail image next to the title is currently unclickable. This improvement wraps the image in the same link so tapping the thumbnail navigates to the Wikipedia page, matching the common mobile UX pattern where the leading image and title are a unified tap target.

---

## Approach

One targeted change to `EventMobileCardV2.jsx`. The `titleHref` value (already computed from `safeHref(wikipediaUrl) ?? safeHref(wikidataUrl)`) is reused — no new logic needed. When `titleHref` is `null` (both URLs absent or unsafe), the image remains a plain non-interactive element, consistent with how the title already degrades to a `<span>`.

The image fallback `<div>` (shown when `imageUrl` is absent or unsafe) is also wrapped in the same link, so the tap target is consistent regardless of whether a real thumbnail loaded.

**Accessibility strategy**: the title `<a>` is the primary interactive and AT-accessible entry point for each card. The image link is `aria-hidden="true"` (and `tabIndex={-1}`) so it is invisible to the accessibility tree — screen readers and keyboard users interact exclusively through the title link and are not exposed to a duplicate link to the same destination. Pointer device users gain the image as a second tap target.

> **Note**: `tabIndex={-1}` alone only removes the element from the Tab key order; assistive technologies navigating in browse/virtual-cursor mode (NVDA, JAWS, VoiceOver arrow-key navigation) still encounter a `tabIndex={-1}` link. `aria-hidden="true"` is required to fully remove the redundant link from the AT accessibility tree.

Then in the JSX, replace the current image block with:

```jsx
{titleHref ? (
  <a
    href={titleHref}
    target="_blank"
    rel="noopener noreferrer"
    aria-hidden="true"
    tabIndex={-1}
    className="flex-shrink-0 cursor-pointer">
    {imageEl}
  </a>
) : imageEl}
```

**`aria-hidden="true"` + `tabIndex={-1}` rationale**: the title `<a>` to the right is the sole AT-accessible and keyboard-accessible link per card. `aria-hidden` removes the image link from the accessibility tree entirely — screen readers in both browse mode and Tab navigation will not encounter it. `tabIndex={-1}` is belt-and-suspenders to additionally exclude it from Tab order for non-AT keyboard users.

**`cursor-pointer`**: without this class, `<img>` elements inside `<a>` tags show `cursor: auto` instead of `cursor: pointer` in some browser/OS combinations. Adding `cursor-pointer` ensures the image appears interactive for pointer device users (including DevTools mobile emulation, which uses a pointer device).

**`rel="noopener noreferrer"`**: `noreferrer` alone implies `noopener` in modern browsers, but legacy browsers (pre-Chrome 49, pre-Firefox 52) do not honour this implication, leaving `window.opener` accessible. Explicit `noopener` eliminates tab-nabbing unconditionally. Apply the same change to the existing title `<a>` at line 72 (`rel="noreferrer"` → `rel="noopener noreferrer"`).

**ESLint comment placement**: the `// eslint-disable-next-line @next/next/no-img-element` comment must appear on the line immediately before the `<img>` tag inside the `imageEl` `const`, as shown above — not above the ternary or above the `const` declaration. This is the same rule as in the current component.

**`flex-shrink-0` on children**: the existing `<img>` and fallback `<div>` both carry `flex-shrink-0`. After wrapping, they are no longer direct flex children of the card's `flex gap-3` container — `flex-shrink-0` on them becomes a no-op. Leave the classes in place (removing them is unnecessary churn); add `flex-shrink-0` to the `<a>` wrapper as shown.
