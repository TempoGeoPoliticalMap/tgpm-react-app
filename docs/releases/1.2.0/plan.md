# Mobile View for Daily News Checks

## Context

The app currently provides four views (table, timeline, map, compact) that are all designed for desktop screens with fixed heights (600px) and wide layouts. On mobile devices these views are unusable. The goal is to auto-detect mobile viewports and replace the desktop views with a Wikipedia-style scrollable news-feed list — showing event thumbnail, name, short description, dates, and a Wikipedia link. Filters are hidden on mobile for a minimal, news-feed-like experience.

> **Note on filter state**: Hiding the filter bar only suppresses the UI. The `selectedTypes`, `fromDate`, and `toDate` state still flows into `EventsV2` and the API call on mobile. This is intentional — filters set on desktop are preserved across a resize. If the design intent changes to "no filtering on mobile," the `typeFilter`/`fromDate`/`toDate` props must also be reset in the mobile branch.

---

## Approach

Six targeted changes across new and existing files. The view switching state remains in `pages/index.js`; on mobile it is forced to `"mobile"` and the view-switcher dropdown is hidden by passing an empty `views` array to `MinimalHeader` (which already short-circuits rendering at line 70: `views.length > 0`). The filter bar is also hidden on mobile by passing `filtersNode={null}`.

**Implementation order matters**: update `EventsV2` (step 5) to add the `"mobile"` entry to the content map *before* wiring the view-switch in `pages/index.js` (step 4). Reversing the order causes `EventsV2` to silently render nothing when `activeView` is `"mobile"` and the content map key does not yet exist.

## Files to Create

### 1. `src/hooks/useMobileDetect.js`
Custom hook using `window.matchMedia` with SSR safety (initialises to `false`, updates after mount).

```js
import {useEffect, useState} from "react";

export function useMobileDetect(breakpoint = 768) {
  const [isMobile, setIsMobile] = useState(false);
  useEffect(() => {
    const mq = window.matchMedia(`(max-width: ${breakpoint}px)`);
    setIsMobile(mq.matches);
    const handler = e => setIsMobile(e.matches);
    mq.addEventListener("change", handler);
    return () => mq.removeEventListener("change", handler);
  }, [breakpoint]);
  return isMobile;
}
```

**SSR / hydration note**: The hook initialises to `false` on the server, so the first render always produces desktop markup. On mobile, after mount the view switches to `"mobile"`, causing a brief flash of the desktop layout before the mobile list appears. To minimise the flash, wrap the desktop-only elements (`EventsTableV2`, etc.) with a CSS class that hides them below the breakpoint (`hidden md:block` or equivalent) so the layout shift is invisible even before the JS effect runs.

**Tests** (`src/hooks/__tests__/useMobileDetect.test.js`):
- Mock `window.matchMedia`; assert `isMobile` is `true` when `matches: true`.
- Assert the `"change"` listener updates state.
- Assert cleanup removes the listener.

// Add import
import {useMobileDetect} from "../src/hooks/useMobileDetect";

// Inside Home():
const isMobile = useMobileDetect();

// Auto-switch view when breakpoint changes.
// Uses functional setState to avoid capturing stale activeView in the closure
// and to satisfy react-hooks/exhaustive-deps (activeView is not a dependency).

  if (isMobile) {
    setActiveView("mobile");
  } else {
    setActiveView(prev => prev === "mobile" ? "table" : prev);
  }
}, [isMobile]);

**iOS Safari / mobile scrolling**: The current outer wrapper (`<div className="flex h-screen overflow-hidden">`) uses `h-screen`, which maps to `100vh`. On iOS Safari, `100vh` is taller than the visible viewport because the browser chrome (URL bar) is not subtracted, causing the bottom of the card list to be obscured. Fix by replacing `h-screen` with `h-[100dvh]` (dynamic viewport height, supported in all modern mobile browsers) or switching to a CSS-variable approach (`min-height: -webkit-fill-available`). The inner `overflow-y-auto` div handles actual scrolling and does not need changes.
